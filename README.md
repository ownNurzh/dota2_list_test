# DOTA қауым

Сайт нашей компании: собираемся по 30 человек, делимся на команды по пять и играем друг против друга в собственных лобби Dota 2. Здесь знакомые ники, фирменные герои, байки из лобби и турнирная сетка. Nuxt 4, Vue 3 и TypeScript, адаптивная раскладка для телефона и компьютера.

Список содержит 34 игрока. Имена, MMR, тиры, заметки и теги сохранены; каждый профиль имеет уникальный ID. Роли задаются числами от 1 до 5.

Сайт: **https://ownnurzh.github.io/dota2_list_test/**

## Запуск

Нужен Node.js 22 или новее.

```sh
npm install
npm run dev
```

В Windows PowerShell при запрете запуска `npm.ps1` используйте `npm.cmd` вместо `npm`.

Откройте адрес, который выведет Nuxt (обычно `http://localhost:3000`).

```sh
npm run build       # production-сборка
npm run preview     # просмотр production-сборки
npm run generate    # статическая версия в .output/public
npm run typecheck   # проверка TypeScript
npm test           # данные игроков, рейтинг и обе турнирные сетки
npm run verify:static # проверка сгенерированных страниц и путей
```

## Структура

- `app/data/players.ts` — единственный источник данных игроков, характеристик и весов рейтинга.
- `app/data/tournaments.ts` — общая история чемпионов: даты, команды-победители и их игроки.
- `app/utils/players.ts` — расчёт балла, поиск, сортировка, форматирование и пути изображений.
- `app/pages/index.vue` — каталог, рейтинг и избранное.
- `app/pages/players/[id].vue` — отдельная страница каждого игрока.
- `app/pages/tournament.vue` — сетка турнира для 4, 6 и 8 команд.
- `app/utils/tournament.ts` — круговой этап, таблица мест, одиночная и двойная сетки, проверка составов и сохранённых данных.
- `app/composables/useTournament.ts` — состояние турнира и сохранение в браузере.
- `app/pages/tournaments/history.vue` — компактный список чемпионов с поиском по дате, команде и игроку.
- `app/composables/useTournamentHistory.ts` — сохранение чемпионов в браузере и чтение старых архивов.
- `app/components/TournamentBracket.vue` — переключение этапов и раундов, обзор этапа и переходы между матчами.
- `app/components/TournamentMatch.vue` — матч, участники и выбор победителя.
- `app/components/PlayerCard.vue`, `StatRadar.vue` — карточка и диаграмма навыков.
- `app/composables/useFavorites.ts` — избранное в localStorage, без регистрации.
- `app/assets/css/main.css` — общие стили и адаптивная раскладка.
- `public/images` — локальная заглушка на случай недоступности изображений. Арты героев загружаются с официального CDN Dota 2; права на персонажей принадлежат Valve.
- `legacy/index.html` — исходный одностраничный проект для справки.

## Данные и рейтинг

Чтобы добавить игрока, добавьте запись с уникальным `id` в `players.ts`. Профиль `/players/<id>` появится автоматически. Для нового героя добавьте сопоставление с именем файла на CDN в `getHeroSlug`.

Поле `role` — число, без кавычек:

| Значение | Позиция |
| --- | --- |
| `1` | Керри |
| `2` | Мидер |
| `3` | Оффлейнер |
| `4` | Софт-саппорт |
| `5` | Хард-саппорт |

Например, `role: 3`. Подписи интерфейса берутся из `roleDefinitions`, поэтому их не нужно повторять в каждой записи игрока.

Пять характеристик задаются вручную по шкале 0–100. Добавленные значения **демонстрационные**, они не получены из матчей или API. MMR и тиры сохранены из исходного списка и не являются живыми данными.

```text
Рейтинг = округление(
  механика × 0.25 + фарм × 0.20 + командная игра × 0.20
  + понимание игры × 0.25 + универсальность × 0.10
)
```

MMR не входит в формулу. Баллы, топ и карточки рассчитываются из одних и тех же данных. При равенстве балла порядок определяется MMR и ником. Избранное хранится только в текущем браузере. Шрифты Manrope и Unbounded загружаются из Google Fonts с системным запасным шрифтом.

## Турнир своих лобби

На странице `/tournament` можно выбрать 4, 6 или 8 команд. Для нового турнира по умолчанию открываются 6 команд: круговой этап, затем двойная сетка для лучших четырёх.

Сетка разделена на вкладки этапов: группа, верхняя сетка, нижняя сетка и финал — набор зависит от формата турнира. В режиме «По раундам» виден выбранный тур или раунд; можно переключаться кнопками раундов и «Назад» / «Дальше». Режим «Весь этап» показывает раунды рядом с горизонтальной прокруткой. На телефоне матчи выбранного раунда идут одной колонкой, а обзор этапа прокручивается внутри сетки. Кнопка «К доступному матчу» открывает следующий матч, в котором уже определены оба участника. Переходы в карточках показывают, куда попадут победитель и проигравший.

- **6 команд:** пять круговых туров по три матча. Каждая команда встречается со всеми остальными — пять игр для каждой, без свободных проходов. В плей-офф выходят четыре лучших по победам. При равенстве побед выше начальный посев; правило показано рядом с таблицей. Пары полуфиналов: 1–4 и 2–3 по итогам группы.
- **4 или 8 команд:** сразу плей-офф.
- **Одиночное выбывание в плей-офф:** после первого поражения команда выбывает.
- **Двойное выбывание в плей-офф:** первое поражение переводит команду из верхней сетки в нижнюю, второе завершает её участие. Поражения кругового этапа не учитываются в плей-офф.
- Один матч — одна игра (BO1).
- Введите названия команд и выберите до пяти игроков на команду из `players.ts`. Один игрок не может быть в двух командах. Поиск помогает найти ник, имя или позицию. Неполные составы разрешены и явно отмечены; фиктивные игроки не добавляются. Для восьми полных команд нужно добавить в список ещё игроков.
- При желании перемешайте посев и выбирайте победителя каждого сыгранного матча. В круговом этапе можно вводить результаты любого тура, но плей-офф откроется только после всех 15 игр.
- Нажатие на команду сохраняет её победу. Повторное нажатие на выбранного победителя оставляет результат; для отмены есть отдельная кнопка «Отменить результат». Чтобы исправить победителя, выберите другую команду в этом матче.
- В двойном формате победители верхней и нижней сеток встречаются в гранд-финале. Если побеждает команда из верхней сетки, она становится чемпионом. Если побеждает команда из нижней, появляется решающий повторный финал: у обеих команд теперь по одному поражению.
- Победители и проигравшие автоматически попадают в нужные матчи. Чемпион появляется только после завершения решающего финала.
- Если изменить результат группы, весь плей-офф сбрасывается, а другие групповые результаты сохраняются. В плей-офф сбрасываются только зависимые матчи по пути победителя и проигравшего.
- Сброс результатов сохраняет названия и составы команд. Изменение количества команд, типа сетки и новый посев очищают результаты после подтверждения, если турнир уже начат.
- Ранее начатые турниры сохраняют прежнюю схему и результаты. При явном сбросе старой сетки на 6 команд включается круговой этап. Старые турниры без результатов переходят на новую схему автоматически.

| Команд | Одиночная сетка | Двойная сетка |
| --- | --- | --- |
| 4 | 3 матча | 6–7 матчей |
| 6 | 15 в группе + 3 = 18 | 15 в группе + 6–7 = 21–22 |
| 8 | 7 матчей | 14–15 матчей |

Дополнительный матч в двойной сетке — повторный гранд-финал, когда он необходим.

Названия и результаты сохраняются только в текущем браузере. Это локальная сетка организатора: другие посетители не видят ваши изменения автоматически. Общая серверная синхронизация и авторизация не подключены.

## История чемпионов

После решающего финала укажите дату и нажмите «Сохранить в историю». Название победившей команды и её состав сохранятся автоматически. Последующие изменения текущей сетки не переписывают эту запись. На странице `/tournaments/history` только дата, команда-победитель и список игроков со ссылками на профили. На телефоне записи складываются в карточки. Поиск учитывает дату, название команды, ник и имя игрока.

Сохранённые вами результаты доступны в этом браузере; их можно удалить с подтверждением. Лимит новых локальных сохранений — 100 записей. Старые архивы с полной сеткой продолжают открываться: из завершённого турнира извлекаются победитель и его состав.

Общая история берётся из `app/data/tournaments.ts` и видна всем посетителям. Чтобы добавить результат, внесите в массив `tournaments` запись с уникальным `id`, датой в формате `YYYY-MM-DD` и полем `champion`. Например, запись из общей истории:

```ts
{
  id: 't1',
  date: '2026-09-26',
  champion: { name: 'Daiteris', playerIds: ['p1', 'p2', 'p3'] },
}
```

`champion.name` — название команды, `champion.playerIds` — до пяти уникальных ID реальных игроков из `players.ts`. После отправки изменений в GitHub общая история обновится при сборке Pages. Проверка `verify:static` проверяет дату, название победителя и ссылки на профили каждого игрока в опубликованной записи.

## GitHub Pages

Публикацией управляет `.github/workflows/deploy-pages.yml`. Каждый push в `main` запускает установку через `npm ci`, тесты, проверку TypeScript и `npm run generate`. После проверки готовые файлы из `.output/public` публикуются в GitHub Pages. Workflow можно запустить вручную во вкладке Actions.

В настройках репозитория **Settings → Pages → Source** используется **GitHub Actions**. Base URL определяется из настроек Pages, поэтому ссылки, favicon и заглушки изображений работают в подпапке `/dota2_list_test/`. Все профили предварительно генерируются — прямые ссылки работают без Node.js-сервера.

Проверка такой же сборки локально в PowerShell:

```powershell
$env:NUXT_APP_BASE_URL = '/dota2_list_test/'
npm.cmd run generate
npm.cmd run verify:static
Remove-Item Env:NUXT_APP_BASE_URL
```

Сайт о своей компании остаётся доступен любому, у кого есть ссылка: GitHub Pages здесь не требует входа. Счётчики показывают весь состав из файла, а не присутствие онлайн.

Настройка соответствует [документации Nuxt для GitHub Pages](https://nuxt.com/deploy/github-pages) и [GitHub Pages с GitHub Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
